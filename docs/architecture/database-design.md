# PENSA GCTU CMS — Database Design

**Engine:** Cloudflare D1 (SQLite) · **Source of truth:** [`db/schema.sql`](../../db/schema.sql) · **Date:** 2026-06-04

This document explains the schema, conventions, and the migration/seed strategies, and provides forward-compatible DDL for the planned modules (Finance, Events, Volunteer, Alumni) and Mobile App sync.

---

## 1. Tables (v1)

| Group | Tables |
|---|---|
| Identity & access | `roles`, `users`, `sessions`, `password_reset_tokens`, `audit_log` |
| Reference / lookups | `cells`, `departments`, `programmes`, `gathering_types` |
| Members | `members`, `member_departments`, `membership_history` |
| Registration pipeline | `registrations` |
| Events | `events` |
| Attendance | `attendance_sessions`, `attendance_records` |
| Generic seams | `attachments`, `settings` |

---

## 2. Relationships

| Parent → Child | Cardinality | FK action | Rationale |
|---|---|---|---|
| roles → users | 1:N | `RESTRICT` | Never delete a role still in use |
| users → sessions | 1:N | `CASCADE` | Sessions die with the user |
| users → audit_log | 1:N | `SET NULL` | Preserve the trail even if actor removed |
| cells → members | 1:N | `SET NULL` | Member keeps existing if cell removed |
| programmes → members | 1:N | `SET NULL` | Same |
| members ↔ departments | M:N via `member_departments` | `CASCADE` both | Join rows are derived data |
| members → membership_history | 1:N | `CASCADE` | History belongs to the member |
| registrations → members | 1:1 (nullable) | `SET NULL` | A registration becomes a member on approval |
| gathering_types → attendance_sessions | 1:N | `RESTRICT` | Can't delete a type with recorded sessions |
| events → attendance_sessions | 1:N (nullable) | `SET NULL` | A session may or may not be tied to an event |
| attendance_sessions → attendance_records | 1:N | `CASCADE` | Records belong to their session |
| members → attendance_records | 1:N | `CASCADE` | Records belong to their member |

`PRAGMA foreign_keys = ON` is set in the schema and enforced by D1.

## 3. Indexes (and why)

- **Partial unique indexes** (`... WHERE deleted_at IS NULL`) enforce natural-key uniqueness only among *live* rows, so a soft-deleted record never blocks re-use of a name/email/phone: `ux_users_email_live`, `ux_members_phone_live`, `ux_*_name_live`.
- **Filter columns** carry indexes used by list screens: `ix_members_membership_status`, `ix_members_registration_status`, `ix_registrations_status`.
- **Foreign keys** are indexed where we query across them: `ix_members_cell`, `ix_members_programme`, `ix_member_dept_department`, `ix_attendance_member`.
- **Attendance hot path:** `ix_sessions_type_date (gathering_type_id, session_date)` and `ux_attendance_session_member` make "load/mark a session" and "prevent double-marking" O(log n).
- **Sync cursors:** `ix_members_updated (updated_at)` supports delta queries for the future mobile app.
- **Audit lookups:** `ix_audit_entity (entity_type, entity_id)` for per-record history.

---

## 4. Constraints

- **Enums** enforced with `CHECK` (e.g. `membership_status IN ('actual_member','visitor','associate','alumni')`, `attendance_records.status IN ('present','absent','excused')`).
- **Booleans** are `INTEGER ... CHECK (col IN (0,1))`.
- **NOT NULL** on required fields (names, `phone_number`, FKs that must exist).
- **UNIQUE** via partial indexes (live rows) + `ux_member_dept`, `ux_attendance_session_member`.
- **Referential integrity** via FKs with explicit `ON DELETE` behavior (table above).

---

## 5. Audit Logs

`audit_log` is a generic, append-only trail written by the service layer on every sensitive action:

- `actor_user_id` (NULL for system/public actions such as a public registration),
- `action` (`member.create`, `registration.approve`, `member.status_change`, `user.suspend`, …),
- `entity_type` + `entity_id`,
- `changes` as JSON `{"before":{...},"after":{...}}`,
- `ip`, `user_agent`, `created_at`.

It is never updated or deleted. Domain-specific history (member status changes) additionally lives in `membership_history` for first-class querying.

---

## 6. Soft Deletes

- Every mutable domain table has `deleted_at TEXT NULL`; `NULL` = live, a timestamp = deleted.
- All reads filter `WHERE deleted_at IS NULL`; uniqueness is enforced only over live rows (partial indexes).
- Soft delete doubles as a **sync tombstone** for the future mobile app (clients learn a row was removed).
- Immutable ledgers (`audit_log`, `membership_history`, `attendance_records`) are **not** soft-deleted; corrections are new rows (or, for attendance, an `excused`/status change), preserving history.

## 7. Future-Proofing

### 7.1 Mobile App (sync-ready today)
Built into v1 so no redesign is needed later:
- **UUID-style TEXT PKs** generated by app *or* DB (`lower(hex(randomblob(16)))`) → clients create records offline without key collisions.
- **`created_at` / `updated_at` / `deleted_at`** on synced tables → delta sync + tombstones; `ix_members_updated` is the sync cursor.
- **`row_version`** on `members` and `attendance_records`, auto-incremented by trigger → optimistic-concurrency conflict detection.
- **API-first** (the architecture's resource routes already return JSON) → the same endpoints serve a mobile client.

### 7.2 Events Module (extends v1 `events`)
v1 ships a minimal `events` table; the full module adds registration/RSVP without touching existing columns:
```sql
CREATE TABLE event_registrations (
    id          TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
    event_id    TEXT NOT NULL REFERENCES events(id) ON DELETE CASCADE,
    member_id   TEXT REFERENCES members(id) ON DELETE SET NULL,
    guest_name  TEXT,                                  -- non-member RSVP
    status      TEXT NOT NULL DEFAULT 'registered' CHECK (status IN ('registered','attended','cancelled')),
    created_at  TEXT NOT NULL DEFAULT (datetime('now'))
);
-- Banners/flyers reuse the generic attachments table (owner_type='event').
```

### 7.3 Finance Module (giving/expenses ledger)
```sql
CREATE TABLE finance_funds (
    id   TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
    name TEXT NOT NULL,                                -- Tithe | Offering | Project | ...
    is_active INTEGER NOT NULL DEFAULT 1 CHECK (is_active IN (0,1))
);
CREATE TABLE finance_transactions (
    id            TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
    fund_id       TEXT NOT NULL REFERENCES finance_funds(id) ON DELETE RESTRICT,
    member_id     TEXT REFERENCES members(id) ON DELETE SET NULL,   -- nullable: anonymous giving
    direction     TEXT NOT NULL CHECK (direction IN ('income','expense')),
    amount_minor  INTEGER NOT NULL,                    -- store money in minor units (pesewas), never floats
    currency      TEXT NOT NULL DEFAULT 'GHS',
    method        TEXT CHECK (method IN ('cash','momo','bank','card')),
    reference     TEXT,
    occurred_on   TEXT NOT NULL,
    recorded_by   TEXT REFERENCES users(id) ON DELETE SET NULL,
    created_at    TEXT NOT NULL DEFAULT (datetime('now')),
    deleted_at    TEXT
);
CREATE INDEX ix_fin_tx_fund ON finance_transactions(fund_id);
CREATE INDEX ix_fin_tx_member ON finance_transactions(member_id);
CREATE INDEX ix_fin_tx_date ON finance_transactions(occurred_on);
-- Receipts reuse attachments (owner_type='finance_transaction').
```
**Seam in v1:** `members.id` is stable and FK-referenceable; `settings('features.finance')` flag gates the module.

### 7.4 Volunteer Module (scheduling/serving)
```sql
CREATE TABLE volunteer_roles (
    id   TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
    name TEXT NOT NULL,                                -- Usher | Sound | Camera | ...
    department_id TEXT REFERENCES departments(id) ON DELETE SET NULL
);
CREATE TABLE volunteer_assignments (
    id             TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
    member_id      TEXT NOT NULL REFERENCES members(id) ON DELETE CASCADE,
    volunteer_role_id TEXT NOT NULL REFERENCES volunteer_roles(id) ON DELETE CASCADE,
    event_id       TEXT REFERENCES events(id) ON DELETE SET NULL,
    session_id     TEXT REFERENCES attendance_sessions(id) ON DELETE SET NULL,
    serve_date     TEXT NOT NULL,
    status         TEXT NOT NULL DEFAULT 'scheduled' CHECK (status IN ('scheduled','served','no_show')),
    created_at     TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX ix_vol_assign_member ON volunteer_assignments(member_id);
CREATE INDEX ix_vol_assign_date ON volunteer_assignments(serve_date);
```
**Seam in v1:** `departments` and `members` already exist; volunteer roles attach to departments.

### 7.5 Alumni Module (extends member lifecycle)
Alumni are not a separate person table — they are a **member lifecycle state** (`membership_status='alumni'`), so no data migration is ever needed. Extra graduate detail goes in a 1:1 extension:
```sql
CREATE TABLE alumni_profiles (
    member_id        TEXT PRIMARY KEY REFERENCES members(id) ON DELETE CASCADE,
    graduation_year  TEXT,
    current_location TEXT,
    occupation       TEXT,
    employer         TEXT,
    can_mentor       INTEGER NOT NULL DEFAULT 0 CHECK (can_mentor IN (0,1)),
    updated_at       TEXT NOT NULL DEFAULT (datetime('now'))
);
```
**Seam in v1:** `membership_history` already records the transition to `alumni`; the directory filters by status.

## 8. Migration Strategy

**Tooling:** Drizzle Kit generates versioned SQL migrations from the typed schema; Wrangler applies them to D1.

- **Authoritative pair:** `db/schema.sql` is the human-readable design source of truth; the Drizzle schema (`app/lib/db/schema.ts`) mirrors it and **generates** the migration files in `db/migrations/`. The initial migration `0000_init.sql` equals this schema.
- **Forward-only & immutable:** migrations are numbered, append-only, and never edited once merged. Schema changes always add a *new* migration.
- **Apply commands:**
  - Local dev: `wrangler d1 migrations apply pensa-gctu-dev --local`
  - Staging: `wrangler d1 migrations apply pensa-gctu-staging --env staging --remote`
  - Production: `wrangler d1 migrations apply pensa-gctu-production --env production --remote`
- **CI/CD gate:** migrations apply to **staging** automatically on merge to `main`; **production** is applied on a gated release step. Staging must be green before production.
- **Breaking changes use expand/contract** (critical once the mobile app is in the field): (1) add new column/table, (2) backfill, (3) ship code reading both, (4) a later migration drops the old. Never rename-in-place a column other clients still read.
- **SQLite ALTER limits:** SQLite can't drop/alter columns arbitrarily; complex changes use the create-new-table → copy → drop-old → rename pattern within one migration.
- **Rollback/DR:** prefer a forward compensating migration. For incidents, D1 **Time Travel** restores point-in-time; scheduled exports to R2 provide off-platform backups.
- **Module migrations:** Finance/Volunteer/Events-extended/Alumni ship as their own numbered migrations in their phase, gated behind the `settings('features.*')` flags.

## 9. Seed Strategy

Three distinct seed sets, by purpose and environment:

| Set | Contents | Where | Method |
|---|---|---|---|
| **Reference** | roles, cells, departments, gathering_types, settings | all envs (dev/staging/prod) | [`db/seeds/reference.sql`](../../db/seeds/reference.sql) — idempotent (`ON CONFLICT DO NOTHING`, stable IDs) |
| **Programmes** | GCTU programme list (managed dropdown) | all envs | `db/seeds/programmes.sql` — generated from the official list when provided; idempotent |
| **Bootstrap** | first `super_admin` user | all envs | `db/seed.ts` script — reads `SUPER_ADMIN_EMAIL` + password from env, hashes with WebCrypto; **never committed** |
| **Demo** | sample members/attendance | dev/staging only | `db/seeds/demo.sql` — guarded; never run in production |

Principles:
- **Idempotent:** every seed is safe to re-run (stable IDs + `ON CONFLICT DO NOTHING`).
- **FK-ordered:** roles → users → lookups → members → attendance.
- **Secrets out of git:** admin credentials come from environment/Wrangler secrets, not SQL.
- **Apply:** `wrangler d1 execute <db> --file db/seeds/reference.sql [--local | --env <env> --remote]`.

## 10. Money & Time Notes (forward discipline)
- **Money** (future finance) stored as **integer minor units** (`amount_minor`, pesewas) + `currency` — never floating point.
- **Time** stored as **UTC ISO-8601 text**; display-time conversion is the app's job.
